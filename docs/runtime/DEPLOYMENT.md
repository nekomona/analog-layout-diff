# Manual deployment to Virtuoso

Use this guide to install the toolbar on a remote Linux Virtuoso host, update
an existing deployment, or load an installed copy into a new CIW. Deployment
uses the existing Bridge connection; startup and later worker launches belong
to Virtuoso.

## Before you start

- Use Python 3.10 or later in an activated virtual environment containing both
  Layout Diff and `virtuoso-bridge`. Installing Layout Diff alone does not install Bridge.
- Establish passwordless SSH and a responsive Bridge daemon in the intended CIW.
- Arrange the source checkouts as shown below. The installer reads Bridge source
  from the parent checkout; an installed Bridge wheel alone is insufficient.
- Put `uv` on the remote host's PATH. The GUI runtime expects Virtuoso, its IPC
  children, the daemon endpoint and the OA filesystem on the same Linux host.

```text
virtuoso-bridge-lite/
  pyproject.toml
  src/virtuoso_bridge/
  analog-layout-diff/
    pyproject.toml
    scripts/install_runtime.py
```

See [Bridge setup](BRIDGE.md) for package installation, SSH/bastion configuration,
profiles, ports and the full host assumptions.

## 1. Select and verify the intended CIW

From the Layout Diff checkout, with your environment active:

```bash
virtuoso-bridge status
virtuoso-bridge eval '1+2'
```

Require a responsive Virtuoso daemon and a result of `3`. If Bridge is not yet
loaded, run `virtuoso-bridge start` and paste its exact printed `load(...)` line
into the intended idle CIW, then check again. Spectre availability is independent
of these layout operations.

For a named connection, select the same profile for both verification and installation:

```bash
virtuoso-bridge status -p MY_PROFILE
virtuoso-bridge eval -p MY_PROFILE '1+2'
```

## 2. Install the latest checkout

Choose a dedicated absolute deployment directory on the host:

```bash
python scripts/install_runtime.py --destination /absolute/path/to/layoutdiff_runtime --native auto
```

Add `--profile MY_PROFILE` to target a named Bridge connection explicitly.
Without it, the installer uses Bridge's resolved default configuration/profile.

The installer stops an existing Layout Diff worker in that CIW, uploads source
packages, prepares the host virtual environment, optionally builds C++, and
generates and loads `<destination>/startup.il`. It retains the previous app
directory as `app-previous-<token>` when replacing an installation.

| Native backend option | Behavior |
| --- | --- |
| `--native auto` | Build when a C++ compiler is available; Python remains available |
| `--native required` | Require a successful compiler/build path |
| `--native off` | Skip the optional build |

## 3. Update an existing configured CIW

Use the same destination and preserve the current session settings:

```bash
python scripts/install_runtime.py --destination /absolute/path/to/layoutdiff_runtime --profile MY_PROFILE --preserve-runtime-settings --native auto
```

`--preserve-runtime-settings` requires Layout Diff to have been loaded in that
CIW. It retains its runtime root, launch command and pinned Bridge port; the
existing command must belong to the supplied destination. Repository settings,
preferences and accepted merge journals remain under that runtime root.

The update restarts the worker. Existing review windows retain their reconstructed
contents; reopen the revision after restart to attach fresh highlight controls.
The installer does not create a design commit or save an edited source layout.
For concurrent CIWs, use separate verified profiles/ports and runtime state
directories; the standard first installation uses `<destination>/state`.

## 4. Load an already deployed copy later

After loading and verifying Bridge in the intended CIW, enter:

```lisp
load("/absolute/path/to/layoutdiff_runtime/startup.il")
```

Use the actual path generated by your installation. It can also be loaded from
`.cdsinit` after Bridge setup when automatic startup is wanted. Verify that the
saved configuration selects this CIW's port and state directory before reusing
a startup file across sessions.

Loading `startup.il` starts the installed sources. Rerun the installer from an
updated checkout to deploy new sources.

## 5. Confirm the deployment

1. Open **CIW → Layout Diff → Diagnostics / Background service** and confirm
   **Running**. Worker errors and logs are available in the lower CIW menu section.
2. Open a normal layout and check for **Save & Commit**, **History** and **Merge**
   on its toolbar.
3. Verify the selected Git repository before committing. Browse a recorded
   checkpoint and open a temporary review to check the native reconstruction path.

If the controls are absent, check that Bridge responds and that the generated
`startup.il` loaded without errors. A worker PID mismatch means the Bridge port
points at another Virtuoso process. See [connection diagnostics](BRIDGE.md#separate-lifetimes-and-diagnostics)
and [runtime ownership](README.md#ownership-and-shutdown).

Stopping Layout Diff through the CIW controls leaves the shared Bridge daemon
running. The [runtime guide](README.md) explains scratch cleanup, durable state
and restart behavior.
